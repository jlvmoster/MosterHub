## Project Overview

MosterHub is a documentation-only knowledge base — a collection of Markdown files covering engineering best practices, environment setup guides, and development workflows. There is no application code, build system, or test suite.

## Repository Structure

All documentation lives under `docs/`, organized into numbered top-level sections for ordering:

- `docs/01 - Getting Started/` — Onboarding and initial environment setup
- `docs/02 - Best Practices/` — Best practices grouped by topic (Agile, Data, Linux, Mac, React, Security, Windows)

Each top-level section has a `README.md` that serves as its index. The root `README.md` provides a table of contents linking to each section.

## Conventions

- **File naming**: lowercase, hyphen-separated (e.g., `first-time-setup.md`, `data-quality-best-practices.md`)
- **Directory naming**: Title Case for topic directories (e.g., `Data/`, `Mac/`), numbered prefix with Title Case for top-level sections (e.g., `01 - Getting Started/`)
- **New sections**: When adding a new top-level section, assign the next available number prefix and create a `README.md` index inside it. Update the root `README.md` table of contents accordingly.

### Commit Message Guidelines

Follows the [Conventional Commits](https://www.conventionalcommits.org/) specification.

**Format:** `type(scope): description`
- Keep subject line within 50 characters
- Wrap body lines at 72 characters
- Use lowercase for type and scope
- No period at the end
- Be specific and descriptive
- Focus on *why* the change was made, not just *what* changed

**Types:**
- `feat` - New content or files
- `fix` - Corrections to existing content
- `docs` - Meta-documentation (README indexes, table of contents)
- `refactor` - Restructuring without changing content
- `chore` - Maintenance tasks (moving, renaming, config changes)
- `perf` - Performance improvements

**Scopes** (optional, based on top-level sections):
- `getting-started` — Onboarding and setup guides
- `best-practices` — Best practice documents

**Standard Commit Examples:**
```
feat(getting-started): add automatic git signing guide
fix(best-practices): correct Homebrew PATH in zsh template
docs: update root README table of contents
chore: reorganize docs into numbered sections
```

**Large Commits (Multiple Related Changes):**
For commits with significant changes, use a body with bullet points:

```
type(scope): brief header (50 characters)

- First key change or improvement made
- Second important modification or addition
- Third significant update or fix
- Fourth notable change (if applicable)
- Fifth change (if applicable)
```

**Example:**
```
feat(getting-started): overhaul onboarding docs

- Add automatic git signing setup instructions
- Reorganize guides into numbered section directories
- Update root README table of contents with new links
- Remove deprecated environment setup steps
```
